# Slapss — Engineering Log

The technical record of what shipped in each version and *why*. Different audience
from `CHANGELOG.md` (plain user language, source of truth for release notes): this
one is allowed to be technical and should explain the reasoning, the trap that was
hit, and what was and was not validated. Newest first. See `RELEASING.md` step 4.

- **v2.2.1 (Can's call: patch bump)** — Three requests from one user email (2026-09-25, a user switching from a competing app), taken on because each helps most users, not just him. **1. Overlay lead time: slider → preset menu + Custom stepper.** The 17-detent slider (`0, 30 s, 1…15 min`) couldn't take the asked-for 10/15 s without getting worse: every extra non-linear value makes drag precision on a 200pt track harder. Replaced with the calendar-app pattern (Apple Calendar, Google Calendar, Fantastical): a `.menu` Picker over `overlayLeadPresets = [0, 10, 30, 60, 120, 300, 600, 900]`, a divider, and "Custom…" (`overlayLeadCustomTag = -1`, never stored), which reveals a "Custom time:" row with a `Stepper` walking `overlayLeadCustomSteps` (5–55 s by 5, then 1–15 min). New values go in the preset array; the UI no longer grows. Note: the v1.8.1 entry records that a preset-list+stepper was the *second* of four designs for this control; the log doesn't say why it was dropped, and Can accepted this version after the history was raised. Existing users are untouched: `overlayLeadTimeSeconds` is still the raw stored value, no migration. Any value outside the presets shows as Custom with its exact label (the slider used to snap legacy values like 45 s to the nearest detent *for display only*, while the scheduler kept firing at 45 s; the label now tells the truth), and the stepper moves to the next step above/below rather than snapping. Two traps hit while validating: stepping from 90 s landed on 2 min, a preset, so the Custom row vanished under the pointer and the menu jumped — `stepOverlayLead` now sets `overlayLeadCustomChosen`; and the stepper rendered left of its value, moved into an `HStack` after the text with `labelsHidden()`. Also fixed the pre-existing "1 minutes before" (the slider's `minutesFormat` at 60 s): new `settings.alert.early.1min` key. New keys in all 7 languages: `settings.alert.early.{1min,custom,customLabel}`. The stale `AppSettings.overlayLeadTimeSeconds` doc comment (described a seconds/minutes unit picker that no longer existed) was rewritten. **2. Keyword filter (`AppSettings.alertExcludedKeywords: [String]`, default empty).** Deliberately mirrors `onlyAcceptedMeetings`: scheduler-only, in `AlertScheduler.reschedule` right after the RSVP check, same `cancelScheduling` + `continue`, so a matching meeting gets neither the overlay nor the lead notification but stays in the popover agenda. Menu bar countdown left alone, as it is for RSVP-filtered meetings (Can's scope: "no full-screen alert, still visible in the dropdown, looking different"). Reminders are never filtered. Matching is `AppSettings.isAlertExcluded(title:)`: title only, `folding([.caseInsensitive, .diacriticInsensitive])`, match must start at a word boundary (previous character not a letter or number). Chosen over plain `contains` because substring matching makes the app's worst failure — a silently skipped meeting — easy ("pto" would catch "Crypto sync", "lunch" "Brunch"), and over whole-word matching because "vacation" should catch "Vacations". No regex, so nothing the user types is interpreted. Known edge: Turkish dotless `ı` doesn't fold to `i`, so "izin" won't match a title typed "IZIN" with a dotless capital; accepted. The new `$alertExcludedKeywords` sink has `.receive(on: DispatchQueue.main)` because `@Published` emits in `willSet` — see CLAUDE.md; the older sinks have the same lag and were left alone. Settings input is AppKit's `NSTokenField` in a small private `NSViewRepresentable` (`KeywordTokenField` in `SettingsView.swift`), not a dependency; it writes back only when a token is committed (`tokenField(_:shouldAdd:at:)`, deferred one turn because `objectValue` doesn't include the new token yet) or editing ends, never per keystroke, so a half-typed "l" never briefly silences every L-meeting; trims, drops empties, de-dupes case-insensitively. Popover: `AgendaRow` shows a `bell.slash` before a muted (`ink3`) title, prefixes the meta line with "No full-screen alert", and sets it as `.help`; finished (dimmed) rows aren't marked. `HeroCardView` gets a `MetaLine("bell.slash.fill", …)`. New keys in all 7 languages: `settings.alert.excludeKeywords{,.placeholder,.caption}`, `popover.alertOff`. New stored value, local only: `privacy.html`'s "Your preferences (lead-time, enabled calendars, etc.) saved in UserDefaults" already covers it, no site change. **3. Click-protection wrappers.** Corporate gateways rewrite invitation links; the join URL is inside but encoded, so `MeetingLinkDetector` either missed it (SafeLinks `?url=` and Proofpoint v2 `?u=` are percent/dash-encoded, and every provider pattern needs a literal `https://host`) or, worse, matched it with the wrapper's tail attached (Proofpoint v3 keeps the URL literal: `urldefense.com/v3/__https://zoom.us/j/1__;!!abc$` made the Zoom pattern return `…/j/1__;!!abc$`). Graph's `onlineMeeting.joinUrl` is never wrapped, so this hit EventKit notes/location and Graph `bodyPreview` only. Fix: `firstURL` first runs `unwrapClickProtection(in:)`, which finds wrapper links (`*.safelinks.protection.{outlook.com,office365.us,outlook.de}`, `urldefense[.proofpoint].com`, `linkprotect.cudasvc.com`) and replaces each with its decoded inner URL; two passes for one wrapper nested in another. Decoders: SafeLinks `url`, Proofpoint v1 `u`, Barracuda `a` via `URLComponents.queryItems`; Proofpoint v2 `-`→`%`, `_`→`/`, then percent-decode; Proofpoint v3 fills each `*` from the urlsafe-base64 segment after `__;`, `**X` being a run of (index of X in `A–Z a–z 0–9 - _`) + 2 characters, then repairs a collapsed `https:/`. All local, no network. Written from memory, then cross-checked against a public reimplementation of Proofpoint's reference decoder (gist `stain/urldecoder.py`); not checked against Proofpoint's own code. Safety properties, both by construction: a wrapper that fails to decode (or decodes to non-http, e.g. `javascript:`) stays in the text untouched, so a format change degrades to pre-2.2.1 behaviour, not a new failure; and the existing provider patterns still decide what counts as a join link, so an unwrapped non-meeting URL is ignored. Trade-off stated in CHANGELOG: Join skips the company's click-time scan, only for recognized meeting providers. Mimecast/Cisco use opaque tokens that only resolve with a network request, which the privacy claim rules out; left alone. `MeetingURLOpener` unchanged; an unwrapped Teams URL takes the existing `msteams://` path. `support.html` "The Join button isn't showing" is still accurate; a sentence about wrapped links is proposed, not made. **Version:** `MARKETING_VERSION` 2.2.0 → 2.2.1 (both configurations); `CURRENT_PROJECT_VERSION` untouched, Xcode Cloud owns it. **Validation:** `xcodebuild build … CODE_SIGNING_ALLOWED=NO` succeeded after each change. Picker, driven through Accessibility on the Debug demo build: legacy 90 s shows Custom with "90 seconds before"; stepping 90 s → 2 → 3 → 2 → 1 minute → 55 s keeps the row; picking "10 seconds before" hides it; Turkish menu and Custom row seen in screenshots. Only English and Turkish layouts were seen; VoiceOver speech not listened to. Keyword filter: an 11-case `swiftc` harness over `isAlertExcluded` passed; demo data with the meeting 5 s out showed no overlay window with keyword "design" and a full-screen window with an empty list; popover marking (row + hero) and token chips seen in screenshots; Can typed, deleted and persisted keywords by hand. The lead-notification suppression wasn't observed directly; it is the same `cancelScheduling` path the RSVP filter uses. Unwrapping: a 16-case `swiftc` harness over the real `MeetingLinkDetector.swift` passed (SafeLinks incl. `&amp;` and GCC, Proofpoint v1/v2/v3 incl. single `*`, `**X` run and `https:/` repair, Barracuda, nesting, non-meeting, broken wrapper, Mimecast, `javascript:`). **Every wrapped sample was synthesized from the documented formats; no real invitation has been tested.** Harnesses live outside the repo (no test target).
